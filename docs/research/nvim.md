# vim / nvim 조사: 철학, 와우 포인트, 그래프로 옮기기

> 조사 문서입니다. 정한 것은 없습니다. [vim에서 더 가져올 것](../vim-ideas.md), [리더 키·검색·줌](../leader-and-zoom-ideas.md), [진단 도구](../diagnostics-ideas.md)에 이미 있는 제안은 다시 풀지 않고 표에 "제안됨"으로만 적었습니다.
>
> 상태 표기: **구현됨** = [키맵](../keymap.md)에 있음 · **제안됨** = 기존 제안 문서에 있음 · **새 제안** = 이 문서에서 처음 나옴

## 1. 철학

vim이 오래 살아남은 이유는 키 개수가 아니라 **작은 규칙 몇 개가 곱해진다**는 점입니다. 아래 개념은 서로 독립이 아니라 한 덩어리입니다. 문법이 있어서 `.`이 의미가 있고, `.`이 있어서 매크로가 짧아지고, 텍스트가 전부라서 `:g`가 모든 것에 걸립니다.

| 개념 | vim | 왜 강한가 |
|---|---|---|
| 문법 (동사 + 명사) | `d` `c` `y` `=` `gu` × `w` `}` `ip` `i"` `t,` | 연산자 N개 + 범위 M개를 외우면 N×M 명령. 새 연산자(플러그인)도 기존 범위를 모두 공짜로 받음 |
| 텍스트 객체 | `iw` `ap` `i(` `it` | 커서가 **어디에 있든** "이 단어", "이 괄호 안"을 지정. 위치를 맞추는 수고가 없음 |
| 모드 | Normal 이 기본, Insert 는 잠깐 | 키 하나하나가 명령이 됨. "편집은 대부분 읽고 고치는 일"이라는 전제 |
| 숫자 | `3dw`, `5j` | 반복을 말로 함. 상대 줄 번호와 짝 |
| `.` 반복 | 마지막 **변경** 한 단위를 반복 | "한 번 정확히 하고, 나머지는 `.`". Practical Vim 의 핵심 |
| 레지스터 | `"a` `"0` `"+` | 복사가 하나가 아니라 이름 붙은 여러 칸. 지운 것도 버려지지 않음 |
| 마크·점프 목록 | `ma` `'a`, `Ctrl-o` `Ctrl-i`, `g;` | 멀리 뛰어도 돌아올 길이 항상 있음 → 과감하게 뜀 |
| 매크로 | `qa…q`, `@a`, `@@`, `10@a` | 매크로 = 레지스터 안의 키 텍스트. 고치기도 텍스트 편집 |
| ex 명령줄 | `:s`, `:g/pat/cmd`, `:normal`, `:cdo` | 일괄 작업을 한 줄로. Normal 명령을 조건부로 대량 적용 |
| 모든 것이 텍스트 | 버퍼, 레지스터, 매크로, 명령 기록 | 같은 도구로 전부를 다룸 |
| 찾아서 이동 | `/` `*` `n`, 이후 telescope·flash | 눈으로 본 곳에 "어떻게 가지"를 고민하지 않음 |
| 발견성 | which-key, `:help` | 문법이 크니 "다음에 뭘 누를 수 있지"를 보여줘야 함 |
| 목록 | quickfix, location list | 컴파일 오류·검색 결과를 목록으로 받아 `]q` 로 순회, `:cdo` 로 일괄 수정 |

## 2. 와우 포인트 (영향 순)

사람들이 vim 에 "빠지는" 순간을 체감 크기 순으로 정리했습니다.

| 순위 | 순간 | 왜 오래 남는가 |
|---|---|---|
| 1 | **문법이 "말"이 되는 순간.** `ci"` 를 처음 쳤을 때, 처음 보는 조합 `dt)` 가 그냥 됐을 때 | 외운 것이 아니라 **추론해서** 맞힘. 이후 모든 학습이 가속 |
| 2 | **`.` 반복** | 반복 작업이 키 하나. "다른 에디터로 못 돌아가는" 이유 1순위로 자주 꼽힘 |
| 3 | **보고 뛰기 (flash / leap / hop, `/`)** | 화면에 보이는 곳 어디든 2~3타. 마우스보다 빠르다는 것을 처음 체감 |
| 4 | **퍼지 찾기 (telescope)** | 이름 일부만 쳐서 파일·심볼·명령 어디든. 프로젝트 크기와 무관하게 같은 속도 |
| 5 | **매크로로 수십 곳을 한 번에** | 정규식으로 안 되는 반복을 녹화로 해결 |
| 6 | **`:g` / `:cdo` 일괄 작업** | "조건에 맞는 모든 곳에 이 명령" |
| 7 | **점프 목록 `Ctrl-o`** | 길을 잃지 않음 → 탐색이 과감해짐 |
| 8 | **LSP: `gd`, `K`, `]d`, rename, code action** | 코드를 "읽는" 도구. 오류 사이를 키로 순회 |
| 9 | **which-key** | 문법의 벽을 낮춤. 처음 쓰는 사람도 "다음 키"를 찾아감 |
| 10 | **surround, treesitter 텍스트 객체** | "함수 하나 통째로 지우기", "괄호 바꾸기" 같은 구조 편집 |
| 11 | **`Ctrl-a` / `Ctrl-x` 숫자 증감** | 작지만 첫 만남에 감탄이 큼 |
| 12 | **oil.nvim: 파일 목록을 텍스트로 편집** | "모든 것이 텍스트"의 극단. 대량 이름 바꾸기가 그냥 편집 |

## 3. 그래프로 옮기기

### 3.1 텍스트 객체 = 그래프의 "모양"

vim 의 텍스트 객체는 "커서가 안쪽 어디에 있든 이 구조 전체"입니다. 그래프에도 커서와 무관하게 정해지는 구조가 있습니다. 다만 [기존 결정](../vim-ideas.md#1-문법-연산자--범위)대로 `i`/`a` 접두어는 쓰지 않습니다 (`i` = 입력).

| vim | 그래프 대응 | 상태 | 키 후보 |
|---|---|---|---|
| `{` `}` 사이 = 문단 `ap` | **덩어리 (island)**: 와이어로 이어진 연결 요소. `==` 가 이미 쓰는 단위 | 정렬에만 구현됨 (`==`) | `{연산자}p` (paragraph). `yp` = 덩어리 복사, `gcp` = 덩어리 끄기 |
| 상류 / 하류 끝까지 | 원뿔 | **구현됨** (`H` / `L`) | |
| `it` / `at` (태그 안 / 태그째) | **그룹 안 객체 / 그룹까지** | 제안됨 (키 미정) | `{연산자}G` 안쪽만, 그룹 객체까지는 비주얼에서 따로 |
| `if` / `af` (treesitter 함수) | **클러스터** 하나 | 새 제안 | 클러스터 위에서 `yy` 이면 충분. 범위 키는 불필요 |
| 같은 열의 줄 | **같은 층(열)** 전체 | 새 제안 | `{연산자}J` / `{연산자}K` (열의 아래 / 위 끝까지) |
| 입력 n 하나의 출처 | **입력 n 의 상류 원뿔** | 새 제안 | `gi{n}` 을 모션처럼: `ygi1` = 커서 + 입력 1 쪽 상류만. `H` 는 모든 입력 |
| 두 지점 사이 | 두 객체 사이 경로(들) | 비주얼 모드가 사각형으로 대신함 (구현됨) | 경로 기반 선택은 보류 |
| treesitter 증분 선택 (`v` 를 누를수록 부모 노드로 확장) | **선택 확장 사다리**: 객체 → 1단계 이웃 → 덩어리 → 그룹 | 새 제안 | 비주얼에서 `+` / `-`. 범위 키를 몰라도 되는 입문용 |

### 3.2 이동과 찾기

| vim | 그래프 대응 | 상태 |
|---|---|---|
| `hjkl`, 숫자 | 와이어·층을 따라 이동 | **구현됨** |
| `{` / `}` 문단 이동 | **이전 / 다음 덩어리**로 (화면 위→아래 순) | 새 제안. `j`/`k` 가 덩어리 끝에서 넘어가는 것보다 명시적 |
| `0` / `$`, `gg` / `G` | 지금 줄기의 **맨 왼쪽 원천 / 맨 오른쪽 끝** (`H`/`L` 의 모션판) | 새 제안. `100h` 대신 |
| `%` 짝 괄호 | **긴 와이어의 반대쪽 끝**, 또는 짝 객체(Relay 양끝, Data Input/Output 송수신, 클러스터 입출력) | 새 제안 |
| `/패턴` `n` `N` | 닉네임·컴포넌트 종류·패널 텍스트로 찾아 순회. `GH_Canvas.ShowSearchDialog` 후보 | 제안됨 |
| `*` / `#` | 커서와 **같은 종류**(ComponentGuid) 다음 / 이전 | 제안됨 |
| `gd` 정의로 | 클러스터 **안으로 들어가기**, 무선 수신기 → 송신기 | 새 제안 |
| flash / leap / hop | **보이는 모든 객체 위에 1~2글자 라벨**, `s{라벨}` 로 즉시 이동 (자세히 3.3) | 새 제안 |
| telescope | 문서 안 객체 퍼지 목록 (닉네임, 종류, 그룹 이름, 패널 내용). 고르는 동안 화면이 미리 그 객체로 감 | 새 제안 |
| 상대 줄 번호 | 커서 기준 **단계 수 표시**: 부모 쪽 객체에 `2h`, 같은 열에 `3j` 를 흐리게. 숫자 모션을 보고 칠 수 있게 | 새 제안 |

### 3.3 라벨 점프 (flash) 를 그래프에

텍스트보다 그래프에서 더 잘 맞는 기능입니다. 텍스트는 이미 `w` `f` 로 빨리 가지만, 캔버스에는 그런 길이 없어서 마우스가 유일한 "보고 뛰기"였습니다.

| 형태 | 키 (예) | 동작 |
|---|---|---|
| 기본 | `s` → `{라벨}` | 보이는 객체마다 라벨(홈 row 우선 `asdf…`), 누르면 이동. 화면 밖은 대상 아님 |
| 연산자 뒤 (operator-pending) | `ys{라벨}` | 커서 ~ 라벨 객체를 범위로 (비주얼 사각형과 같은 규칙) |
| 원격 (flash 의 `r`) | `o0` → `s{라벨}` → `i1` | **커서를 옮기지 않고** 먼 객체의 입력에 연결. 마우스 드래그를 완전히 대체 |
| 파라미터 라벨 | `i` 대기 중 `s` | 보이는 모든 입력 단자에 라벨 → 연결 대상 한 번에 |

- 라벨은 화면 좌표가 아니라 객체에 붙어야 하고, 매번 같은 객체에 같은 라벨이 가도록 안정적으로(flash 의 "stable labels") 매깁니다.
- 라벨 글자는 다음 키와 겹치지 않게 고릅니다 (flash 가 검색어의 다음 글자를 라벨에서 빼는 것과 같음).

### 3.4 반복과 기록

| vim | 그래프 대응 | 상태 |
|---|---|---|
| `.` | 마지막 변경(연결 + 데이터 연산, `d{범위}`, `gc{범위}`) 반복 | 제안됨 (로드맵) |
| `qa … q`, `@a`, `@@` | 키 입력 녹화·재생. hjkl 이 연결 기반이라 **위치가 아니라 구조로** 재생되는 장점 | 제안됨 |
| `"a` 레지스터 | 이름 붙은 복사 칸 (Grasshopper XML). `"ap` 로 커서 옆에 붙이고 출력 자동 연결 | 제안됨 (`p` 는 로드맵) |
| `gv` | 마지막 비주얼 선택 다시 | 새 제안. 작고 유용 |
| `m{a}` / `'{a}` | 객체에 표시 → 점프. 대문자는 **다른 문서**의 객체까지 | 제안됨 |
| harpoon (1~4번 칸) | 자주 오가는 객체(최종 출력, 주요 슬라이더) 를 번호 칸에. `Ctrl+1..4` | 새 제안. 마크보다 외울 것이 적음 |
| `Ctrl-o` / `Ctrl-i` | 점프 목록. `gi`, `go`, `/`, `s`, `'a` 같은 "먼 이동"만 기록 | 제안됨 |
| `g;` / `g,` 변경 목록 | **최근에 고친 객체**로 되돌아가기 | 새 제안. 점프 목록과 같은 장치로 거의 공짜 |
| undotree | Grasshopper 실행 취소 기록은 일직선 | 들여오지 않음 (4절) |

### 3.5 일괄 작업과 목록

| vim | 그래프 대응 | 상태 |
|---|---|---|
| `:g/pat/cmd` | `:g/type:Mesh/` + Normal 명령. 예: `:g/type:Panel/gcc`, `:g/nick:debug/dd` | 제안됨 |
| `:s/a/b/` | 닉네임 일괄 치환. `:s/^pt/point/` | 새 제안 |
| quickfix | **오류·경고 컴포넌트 목록**. `]e` / `[e` 순회, `:copen` 으로 HUD 목록 | 제안됨 ([진단](../diagnostics-ideas.md)) |
| `:cdo cmd` | 목록 전체에 명령 (예: 경고 난 것 모두 `gc`) | 새 제안 |
| location list | 검색 결과(`/`, `*`) 도 같은 목록 형식으로. `]q` 하나로 순회 | 새 제안 |
| oil.nvim | 선택한 객체들의 **닉네임·슬라이더 값을 텍스트 버퍼로** 열어 고치고 저장하면 반영 | 새 제안. 가치 크지만 무거움, 나중 |

### 3.6 구조 편집

| vim / 플러그인 | 그래프 대응 | 상태 |
|---|---|---|
| `gcc` 주석 | Enable 토글 | **구현됨** (`gc`) |
| `c` 바꾸기 | 와이어 유지하고 컴포넌트 종류 교체 | 제안됨 |
| `o` 아랫줄 열기 | 와이어 사이에 새 컴포넌트 끼워 넣기 | 제안됨 |
| surround `ys` / `ds` / `cs` | **그룹이 감싸기**: `ys{범위}` 범위를 그룹으로 묶기, `ds` 그룹 풀기, `cs` 그룹 색·이름 바꾸기 | 새 제안. 그룹은 Grasshopper 의 괄호 |
| `Ctrl-a` / `Ctrl-x` | **슬라이더 값 증감**, `10 Ctrl-a`. 패널·정수 파라미터도 | 새 제안. 작고 감탄이 큼 |
| `r{문자}` | 슬라이더에 값 바로 입력 (`r` 뒤 숫자 + Enter) | 새 제안 |
| LSP rename | 닉네임 바꾸기 (`cn` 후보) | 새 제안 |
| `J` 줄 합치기 | 범위를 **클러스터로 접기** | 새 제안. 키는 `J` 가 범위 후보와 겹치므로 미정 |

### 3.7 발견성

| vim | 그래프 대응 | 상태 |
|---|---|---|
| which-key | 접두어(`g`, `d`, `y`, `z`, `[`, `]`) 를 누르고 잠시 멈추면 이어질 키 목록을 HUD 에 | 제안됨 |
| `showcmd` | 입력 중인 명령(`2y3`) 을 HUD 에 | 확인 필요 (HUD 에 모드만 표시하는지) |
| `:help` | `:help yL` 처럼 키 설명. 키맵 문서와 같은 출처에서 생성 | 새 제안 |
| LSP `K` hover | 데이터 트리 모양 | 제안됨 |
| inlay hint | 와이어 위 `{3;10}` | 제안됨 |

## 4. 옮기지 말 것

| vim 의 것 | 왜 안 되는가 | 대신 |
|---|---|---|
| `i`/`a` 텍스트 객체 접두어 | `i` = 입력과 충돌. inner/around 차이가 그룹 말고는 없음 | 범위 글자 하나 (`p`, `G`, `H`) |
| 줄 번호·`:42`·linewise/charwise | 그래프에는 전체 순서가 없음. "다음"을 임의로 정하면 "같은 키는 같은 곳" 원칙이 깨짐 | 순서가 필요하면 정렬 결과(열·행) 하나로만 정의 |
| Insert 모드 키 (`Ctrl-w`, `Ctrl-r` …) | 텍스트 입력은 Grasshopper 대화상자·검색창의 일. 텍스트 에디터를 다시 만들 이유 없음 | 값 입력은 `r`, 많으면 oil 식 버퍼 |
| undotree (가지 치는 실행 취소) | Grasshopper 실행 취소는 일직선 기록. 가지를 만들려면 기록을 통째로 대체해야 함 | `u` / `Ctrl+r` 로 충분 |
| 창 분할 `Ctrl-w` | 캔버스 하나. 문서 탭 전환 정도만 | `gt` / `gT` 문서 전환 정도 |
| 접기 `zf` / `za` | Grasshopper 에 객체 숨기기·접기가 없음 | 클러스터로 접기 (3.6), 줌 |
| Visual block `Ctrl-v` | 비주얼 모드가 이미 2차원 사각형 | 없음 |
| 매크로 안의 화면 좌표 이동 | `Ctrl+hjkl`, 라벨 점프는 화면에 따라 결과가 달라 재생이 깨짐 | 매크로에는 연결 기반 모션 권장, 경고 표시 |
| 큰 ex 언어 (vimscript, `:let`, `:if`) | 범위 대비 쓰임이 적음. 그 역할은 C# 스크립트 컴포넌트가 이미 함 | `:g` `:s` `:cdo` 와 Grasshopper 메뉴 명령 몇 개 |
| "설정이 곧 에디터" 문화 | nvim 입문 장벽 1순위. 기본값이 좋아야 함 | 좋은 기본 키맵 + 나중에 설정 파일 |
| 레지스터 남발 (`"0`~`"9`, 지운 것 자동 저장) | Grasshopper 클립보드는 시스템 하나(XML). 숨은 칸이 많으면 혼란 | 이름 붙인 칸 몇 개만, 기본은 시스템 클립보드 |
| 모드 추가 | 모드가 늘수록 "지금 무슨 상태지" 비용 | Grasshopper / Vim / 비주얼 세 개 유지, 대기 상태는 HUD 로 |

## 5. 우선순위 (가치 / 수고)

| 순위 | 기능 | 가치 | 수고 | 근거 |
|---|---|---|---|---|
| 1 | `.` 반복 | 큼 | 작음 | 명령 구조가 이미 있음. 와우 2위 |
| 2 | which-key HUD | 큼 | 작음 | 문법이 커질수록 필수. HUD 이미 있음 |
| 3 | 라벨 점프 `s{라벨}` + 원격 연결 | 매우 큼 | 중간 | 캔버스의 마우스 대체 1순위. 그래프에서 텍스트보다 이득이 큼 |
| 4 | 점프 목록 `Ctrl-o`/`Ctrl-i` + `g;` | 중간 | 작음 | `h`/`l` 이 서로 역이 아닌 문제를 덜어줌 |
| 5 | `]e`/`[e` + quickfix 목록 | 큼 | 작음~중간 | 데이터는 API 로 바로 읽힘 |
| 6 | 덩어리 범위 `p`, `{` `}` 덩어리 이동 | 중간 | 작음 | `==` 의 덩어리 계산 재사용 |
| 7 | `/` `*` `n` 찾기 | 큼 | 중간 | 퍼지 목록(telescope 식)으로 키우면 와우 4위 |
| 8 | 슬라이더 `Ctrl-a`/`Ctrl-x` | 중간 | 작음 | 작지만 첫인상에 강함 |
| 9 | 마크 `m{a}` / harpoon 칸 | 중간 | 작음 | 큰 정의에서 오가는 비용 |
| 10 | surround 식 그룹 `ys{범위}` / `ds` | 중간 | 중간 | 그룹 만들기는 마우스로 번거로운 작업 |

매크로, `:g`, `c` 교체, oil 식 버퍼는 가치가 크지만 `.`·`:` 명령줄·컴포넌트 검색이 먼저 있어야 해서 뒤로 둡니다.
