# 0021. 연산자 뒤 `'{a-z}`는 마크까지 블록, `.`으로 되풀이

- 상태: 채택 (2026-11-10)
- 관련: [키맵 — 연산자 + 범위](../keymap.md#연산자--범위), [0019 라벨 점프](0019-label-jump-t.md), [0011 되풀이](0011-repeat.md), `WireRange.ToMark`, `VimController.ApplyOperator`

## 맥락

vim의 `d'a`처럼 마크를 범위 끝으로 쓰고 싶다. 화면 위치로 고르는 블록 범위는 이미 `t{라벨}`이 있다 ([0019](0019-label-jump-t.md)).

## 결정

- `{연산자}'{a-z}`는 `t{라벨}`과 같은 블록 (커서 객체 ~ 마크 객체, `VisualRange`). 블록 구현은 하나: Engine이 마크를 GUID로 바꿔 `WireRange.To`로 넘긴다.
- 숫자는 앞뒤 모두 무시 (`t`와 같음). 오류는 `'{a-z}` 점프와 같음 (`마크 a가 없습니다`, `마크 a의 객체가 지워졌습니다`).
- `t{라벨}`과 달리 `.`으로 되풀이한다. 마크는 화면이 바뀌어도 같은 객체라서다. 명령에는 GUID가 아니라 **마크 글자**를 담고, 되풀이할 때마다 다시 찾는다 (`ma`로 옮기면 따라감).

## 결과

- `gc'a`, `='a` 뒤 다른 객체에서 `.`이 자연스럽게 된다.
- `d'a` 뒤 `.`은 마크 객체가 지워져서 오류다. 실패한 되풀이는 마지막 변경을 바꾸지 않는다.

## 버린 대안

| 대안 | 버린 이유 |
|---|---|
| 파서가 바로 GUID로 (`WireRange.To`) | 파서는 마크를 모르고, 되풀이 때 `ma`로 옮긴 마크를 따라가지 못함 |
| `t`처럼 되풀이 안 함 | 라벨과 달리 대상이 그대로라 되풀이할 이유가 있음 |
