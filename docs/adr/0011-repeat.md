# 0011. `.`은 지금 커서 객체에서 되풀이, `{n}.`은 단계 수를 바꿈

- 상태: 채택 (2026-11-09)
- 관련: [키맵 — 되풀이](../keymap.md#되풀이), `RepeatRegister.cs`, `VimController.Repeat`

## 맥락

`.`은 vim 와우 포인트 2위입니다. 연산자 + 범위 문법이 생기면서 "같은 변경을 다른 곳에" 할 일이 많아졌습니다.

## 결정

- 마지막 **변경**을 지금 커서 객체에서 다시 실행합니다.
- 되풀이되는 것: `d` `=` `gc` + 범위 (`t{라벨}` 제외, `'{a-z}`는 포함 — [0021](0021-mark-range.md)), `dd` `gcc` `==` `g=`, `di{n}` / `do{n}`, `i{n}` / `I{n}`, 데이터 연산자. 되풀이 안 되는 것: 이동, `y` / `gy`(복사는 변경이 아님), undo/redo, 비주얼 조작, `o{n}`만 고르기, `Space Space`, 실패한 명령(바뀐 것이 없는 것 포함).
- `{n}.`은 숫자 단계 범위의 단계 수를 n으로 바꾸고 이후 `.`도 n단계. `H` `L` `p`와 범위 없는 명령은 숫자 무시.
- 비주얼 변경은 커서 객체 형태로 저장 (`d` → `dd`, `gc` → `gcc`, `=` → `==`). 비주얼 모드 안에서는 `.` 불가.
- 데이터 연산자는 앞의 `o{n}` / `i{n}`과 묶음. `i{n}` 뒤 `.`은 **지금 고른 소스**를 연결합니다 (소스는 연결 후 풀리므로 `o{n}`을 다시 고름).
- 되풀이 한 번은 `u` 한 번 ([0003](0003-undo.md), `MergeRecords`).

## 결과

- 파서는 명령을 내놓기만 하고 무엇을 기록할지는 Core의 `RepeatRegister`가 정합니다. 새 변경 명령을 만들면 여기에 넣을지 정해야 합니다.
