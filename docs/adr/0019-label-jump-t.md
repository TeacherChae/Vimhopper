# 0019. 라벨 점프는 `t`, 연산자 뒤 `t{라벨}`은 커서~대상 블록

- 상태: 채택 (2026-11-10)
- 관련: [로드맵 2텀](../roadmap.md#2텀-찾기와-점프), [0007 비주얼 모드](0007-visual-mode.md), [0010 연산자 + 범위](0010-operator-range.md)

## 맥락

nvim의 flash·leap은 `s`로 라벨 점프를 합니다. Vimhopper에서 `s`는 `o{n}` / `i{n}` 바로 뒤에서 데이터 연산 Simplify이고, 로드맵의 원격 연결(`o0 {라벨 점프} i1`)이 바로 그 자리에서 라벨 점프를 씁니다. 사용자는 `;` `,` 같은 특수문자 키도 원하지 않았습니다.

## 결정

- 라벨 점프는 `t` (target). 데이터 연산 키(`f g s r n`)가 아니라서 `o0 t{라벨} i1`이 그대로 됩니다.
- 연산자 뒤 `t{라벨}`은 범위: 커서 객체와 대상 객체를 두 끝으로 하는 블록 (비주얼 모드의 `v` → 대상과 같은 범위). 예: `yt{라벨}`, `dt{라벨}`, `zt{라벨}`.
- 라벨 점프는 점프 목록에 기록됩니다.

## 결과

- vim의 `t{글자}`(그 앞까지)와 키는 같고 뜻은 다릅니다. Vimhopper에는 글자 단위 이동이 없어서 겹치지 않습니다.
- `s`는 데이터 연산 자리로 남습니다.

## 버린 대안

| 대안 | 버린 이유 |
|---|---|
| `s` + Simplify를 `S`로 | 기존 `o0s` 습관이 깨짐 |
| `s`, 단 `o{n}` 직후에는 Simplify | 원격 연결 때 키를 하나 더 거쳐야 함 |
| `;` / `,` | 사용자가 특수문자 키를 원하지 않음 |
