# 0016. 다음 키 힌트는 표 하나, 테스트가 문법과 양방향으로 맞춤

- 상태: 채택 (2026-11-09)
- 관련: [키맵 — 다음 키 힌트](../keymap.md#다음-키-힌트), `KeyParserHints.cs`, `KeyParserHintTests.cs`

## 맥락

키가 늘어날수록 발견성이 문제입니다 (nvim의 which-key). 힌트를 손으로 관리하면 파서와 금방 어긋납니다.

## 결정

- 접두어(`g` `y` `=` `d` `gy` `gc` `Space`, 숫자, 번호를 기다리는 `o` `i` `gi` …) 뒤 0.4초 멈추면 HUD에 다음 키와 뜻.
- 힌트 표는 `KeyParser`의 partial `KeyParserHints.cs` 한 곳. 파서 상태마다 표 하나.
- 테스트가 양방향으로 검사: 힌트의 키는 모두 파서가 받아들이고, (다음 키가 고정된 상태에서) 파서가 받아들이는 키는 모두 힌트에 있음. **새 키를 파서에 넣으면 힌트 표에도 넣어야 테스트가 통과합니다.**
- `o{n}` / `i{n}` 직후(데이터 연산자 대기)는 평소에 머무는 상태라 띄우지 않습니다.
- 앞 숫자가 있으면 설명에 실제 단계 수 (`2y` → `h` 상류 2단계).

## 결과

- 테스트의 후보 문자 목록(`Every_accepted_key_is_hinted`)에 새 기호·Ctrl 키를 넣어야 빠짐을 잡습니다.
- 알려진 작은 문제: 비주얼 모드에서 숫자 뒤 오류 문구가 쓸 수 없는 `y` `=` `d` `g` `.`까지 나열합니다.
