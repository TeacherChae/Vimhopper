# 0015. 자동 정렬은 직접 구현: Network Simplex 층·좌표, 가로지를 때만 Relay

- 상태: 채택 (2026-10-26, Network Simplex는 2026-10-30)
- 관련: [자동 정렬](../formatting.md), [자동 정렬 개선 조사](../formatting-research.md), `CanvasLayout.cs`, `LayeredLayout.cs`, `NetworkSimplex.cs`, `Formatter.cs`

## 맥락

hjkl이 와이어를 따르므로([0005](0005-hjkl-follows-wires.md)) 화면 배치가 연결 구조와 맞아야 키보드로 따라갈 수 있습니다. 코드 포매터처럼 손대지 않아도 깔끔해져야 합니다.

## 결정

- 외부 도구(Graphviz, ELK, AutoGraph) 없이 Core에 직접 구현합니다 (Sugiyama 계열).
- 층: 모든 객체를 부모보다 오른쪽에 두면서 **와이어가 건너는 열 수의 합이 최소** (Network Simplex). 입력값과 작은 가지가 쓰이는 곳 바로 앞으로 갑니다.
- 세로 위치: `가중치 × 그립 높이 차`의 합 최소. 가중치 줄기 100 > 맨 위 입력 8 > 나머지 1. 맨 위 입력 와이어가 수평이라 `h`/`l`이 수평 와이어를 따라갑니다.
- 풀 수 있는 Relay는 사용자가 넣은 것도 풀고, **와이어가 객체를 가로지르는 곳에만** 새로 놓습니다.
- 결과 확인용 Panel(받기만 하는 것)은 흐름에서 빼서 덩어리 위에 한 줄로.
- **멱등**: 정렬한 것을 다시 정렬해도 그대로, 바뀐 것이 없으면 undo 기록도 없음.
- 키는 vim 문법 `==`(덩어리) / `g=`(전체) / `={범위}`.

## 결과

- 그려진 와이어는 건너뛰는 열의 객체를 가로지르지 않습니다 (양 끝 열의 이웃은 약 4~6% 가로지름).
- 의미상 단계와 그래프 깊이가 어긋나는 문제(Neg 같은 보조 단계)는 남아 있습니다.
- 와이어 곡선 근사(제어점 0.5배)와 undo 순서는 Rhino 확인 필요.

## 버린 대안

| 대안 | 버린 이유 |
|---|---|
| 소스부터 최단 거리 층 | 같은 층 안에 세로 와이어가 생김 |
| 소스부터 최장 거리 층 | 입력값이 모두 맨 왼쪽으로 몰려 와이어가 길어짐 |
| 혼합 (컴포넌트 최장 거리 + 입력값만 앞당김) | `슬라이더 → Unit Z → Extrude` 같은 가지가 화면을 가로지름 |
| 위 열부터 차례로 맞추고 겹치면 밀기 | 서로만 기준으로 삼는 묶음이 가라앉아 빈 띠가 생김 |
| ELK를 플러그인에 넣기 | Java/JS라 Rhino 플러그인에 무거움. 실험에서 얻은 개념(Network Simplex 층, 줄기 가중치, 결과 패널 빼기)만 C#으로 옮김. 입력값끼리 간격 0, 결과 패널 자리는 ELK로 안 됨 ([조사](../formatting-research.md#elk-실험)) |
