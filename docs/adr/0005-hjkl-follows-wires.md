# 0005. hjkl은 와이어를 따르고, 기록 없이 자동 정렬과 같은 기준

- 상태: 채택 (2026-10-26)
- 관련: [이동 (hjkl)](../navigation.md), `GraphNavigator.cs`

## 맥락

Grasshopper 정의는 트리가 아니라 DAG라서 부모도 자식도 여럿입니다. 첫 구현(`TreeNavigator`)은 "어느 방향으로 건너왔나"로 모호함을 풀었는데, 같은 객체에서 같은 키를 눌러도 직전 경로에 따라 결과가 달라 예측할 수 없었습니다.

## 결정

- **현재 객체만 보고** 정합니다. 이동 기록은 쓰지 않습니다.
- `h` = 맨 위(번호가 가장 작은) 연결된 입력의 출처, `l` = 나를 맨 위 입력으로 받는 자식(없으면 가까운 층 → 화면 위쪽 순), `j`/`k` = 같은 층 안 아래/위 (덩어리 경계를 넘어 다음 덩어리의 같은 층으로).
- 층은 자동 정렬의 층 계산(`CanvasLayout.Layers`)을 그대로 씁니다. **정렬된 화면에서는 hjkl이 그대로 좌·하·상·우**입니다.
- Relay에서도 멈춥니다 (갈래가 여럿일 수 있으므로). 층은 Relay를 풀고 계산합니다.
- 화면 방향 이동은 따로 `Ctrl+hjkl`.

## 결과

- 정렬(`==`)과 이동이 서로를 강화합니다: 정렬하면 이동이 눈에 보이는 대로 됩니다.
- `h`와 `l`은 서로의 역이 아닐 수 있습니다 (`l`로 간 자식의 맨 위 입력이 원래 객체가 아닐 때). 그래서 점프 목록([0008](0008-jumplist.md))과 비주얼 `u`([0007](0007-visual-mode.md))를 뒀습니다.
- 맨 왼쪽·끝 객체, 덩어리 경계, 와이어 없는 연결(Galapagos, Timer)에서 `부모 없음` / `자식 없음`이 자주 납니다. 해결 방향은 정하지 않았습니다 ([미해결](../navigation.md#미해결-부모-없음--자식-없음이-자주-나옴)).
- 같은 출력을 받는 다른 층의 자식으로 넘어가는 키가 아직 없습니다.

## 버린 대안

| 대안 | 버린 이유 |
|---|---|
| 이동 기록으로 방향 정하기 (`TreeNavigator`) | 같은 키, 같은 자리인데 결과가 다름 |
| 화면 좌표로 hjkl | 정렬 안 된 화면에서 와이어와 무관하게 움직임. `Ctrl+hjkl`로 따로 둠 |
