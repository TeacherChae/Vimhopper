# 0022. 3텀 키: `]` / `[` 다음·이전, `K` 데이터 모양, `gG` 그룹, `c` 바꾸기

- 상태: 채택 (2026-11-10)
- 관련: [로드맵 3텀](../roadmap.md#3텀-읽기와-진단), [진단 도구](../diagnostics-ideas.md), [0010 연산자 + 범위](0010-operator-range.md)

## 맥락

3텀은 큰 정의를 "읽는" 기능입니다: 오류·경고 사이 이동, 데이터 트리 모양, 그룹, 느린 객체, 별명 바꾸기. vim·nvim에는 이런 키의 관례가 있고, 지금 일반 모드에서 `[` `]` `K` `c` `G`는 비어 있습니다 (`gc`만 있음).

## 결정

| 키 | 뜻 | vim 근거 |
|---|---|---|
| `]` / `[` + 글자 | 다음 / 이전 무엇으로: `e` 오류(원인인 객체만), `w` 경고, `s` 느린 객체, `g` 그룹. 숫자를 받고 점프 목록에 기록 | `]d` 진단, `]c` 바뀐 곳 |
| `K` | 커서 객체의 입력·출력 데이터 트리 모양 | `K` hover |
| `gG{범위}` | 범위를 Grasshopper 그룹으로 묶고 이름을 붙임 (연산자 + 범위 문법, 비주얼 `gG`) | surround `ys` |
| `c` + 글자 | 바꾸기 접두어. 3텀은 `cn` 커서 객체 별명 바꾸기. 나중에 컴포넌트 종류 바꾸기가 같은 접두어를 씀 | `c` change |

- 이름 입력(`gG`, `cn`)은 `/`의 입력줄([0020](0020-search.md))을 그대로 씁니다.
- "원인인 객체"는 오류가 난 객체 중 상류에 오류가 난 객체가 없는 것입니다. 하류로 번진 오류는 건너뜁니다.

## 결과

- `[` `]`가 앞으로 `]c` 바뀐 곳 같은 순회의 자리가 됩니다.
- `c`는 vim처럼 연산자(`c{범위}`)가 아니라 접두어입니다. 범위의 모든 객체 별명을 바꾸는 일은 4텀 `:s`가 맡습니다.

## 버린 대안

| 대안 | 버린 이유 |
|---|---|
| `ge` / `gw` 같은 `g` 접두어 | `g` 아래가 이미 많음 (`g=` `gy` `gc` `gi` `go`), vim 관례와 다름 |
| `c{범위}` 연산자 | 별명 바꾸기는 대개 객체 하나. 여러 개는 `:s`가 더 맞음 |
