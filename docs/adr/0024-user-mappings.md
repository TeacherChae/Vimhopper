# 0024. 사용자 매핑은 파서 앞단에서 펼치고, 명령 입력 중에는 걸지 않음

- 상태: 채택 (2026-11-10)
- 관련: [0023 명령줄·설정](0023-cmdline-config.md), [0012 리더](0012-leader-space.md), [0016 다음 키 힌트](0016-which-key.md), [키맵: 설정](../keymap.md#설정), `KeyRemapper.cs`, `UserConfig.cs`

## 맥락

0023에서 `map` 계열을 vim과 같게 하기로 했습니다. vim에는 모드가 여럿(operator-pending, cmdline …)이고 키 입력이 typeahead 버퍼를 거치지만, Vimhopper의 `KeyParser`는 키 하나씩 받는 상태 머신입니다. 또 Vim 모드는 모르는 키(`Ctrl+S` 등)를 Grasshopper에 넘깁니다.

## 결정

- 매핑은 `KeyParser` 앞의 `KeyRemapper`가 펼칩니다 (typeahead). 키를 하나 넘길 때마다 모드를 다시 물어서, rhs 안의 `v` 뒤 키는 비주얼 매핑을 따릅니다.
- 매핑은 파서가 입력 중인 명령이 없을 때, 반복 횟수만 쳤을 때(`3Q`), `o{n}` 직후에만 겁니다. 연산자·접두어 뒤(`d` 다음)와 입력줄이 열린 동안에는 걸지 않습니다 (vim의 `omap` / `cmap`은 없음).
- 평소에 Grasshopper에 넘기는 키(`;` `,` `-` `Tab` `Ctrl+s` …)는 lhs의 앞부분일 때만 가져갑니다. 기다리는 중에 맞지 않는 그런 키가 오면 모은 키를 먼저 흘려보내고 그 키는 Grasshopper에 넘깁니다.
- Ctrl 조합 표기는 `KeyParser`의 `Ctrl{글자}` 상수를 리플렉션으로 모아 씁니다. 상수가 없는 Ctrl+글자는 매핑 전용 문자(U+E100~)로 나타냅니다.
- vim과 다른 점: rhs 끝 공백은 버림, 모르는 `<이름>`은 오류 (vim은 글자 그대로), 재귀 깊이 100.
- 설정은 엔진마다 갖고, 핫 리로드하면 파일을 다시 읽습니다 (`:set`으로 바꾼 것은 사라짐).

## 결과

- 매핑 없이 쓰는 사람에게는 키 처리가 그대로입니다 (가져가는 키가 늘지 않음).
- `d` 뒤에 쓰는 범위 매핑(`omap`)은 못 만듭니다. 필요해지면 모드를 하나 더합니다.
- 슬라이더 `Ctrl+a` / `Ctrl+x`처럼 `KeyParser`에 Ctrl 상수를 더하면 `<C-a>` 표기가 저절로 그 상수를 가리킵니다.

## 버린 대안

| 대안 | 버린 이유 |
|---|---|
| 매핑을 `KeyParser` 상태에 넣기 | 파서가 커지고, 펼친 rhs를 다시 파서에 넣는 재귀가 생김 |
| 연산자 뒤에도 `map` 적용 (vim의 nvo) | `nmap`과 `map`의 차이를 설명해야 하고, `d` 뒤 키를 가로채면 범위 문법이 깨지기 쉬움 |
| 모든 키를 늘 가져가기 | 매핑하지 않은 `Ctrl+S` 저장 등이 Vim 모드에서 먹통이 됨 |
