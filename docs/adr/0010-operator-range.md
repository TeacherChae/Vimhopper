# 0010. 연산자 + 범위 문법, 범위는 hjkl을 그대로

- 상태: 채택 (2026-11-04)
- 관련: [키맵 — 연산자 + 범위](../keymap.md#연산자--범위), [vim에서 더 가져올 것](../vim-ideas.md), `KeyParser.cs`, `GraphRange.cs`

## 맥락

vim에 빠지는 이유 1위는 키 개수가 아니라 **동사와 범위를 자유롭게 조합**하는 문법입니다 ([nvim 조사](../research/nvim.md)). 새 기능마다 키를 따로 만들면 외울 것만 늘어납니다.

## 결정

- 연산자: `y` 복사, `gy` 참조 복사, `=` 정렬, `d` 삭제, `gc` 켜기/끄기.
- 범위는 새 문법을 만들지 않고 이동 키를 그대로: `h` / `l` 상류 / 하류 한 단계, `{n}h` / `{n}l` n단계, `H` / `L` 끝까지, `p` 덩어리 ([0009](0009-islands.md)).
- 이동은 맨 위 입력 하나만 따라가지만 범위는 **모든 입력·출력 와이어**를 따라갑니다. 커서 객체도 범위에 들어갑니다.
- 숫자는 앞뒤 모두 붙고 곱합니다 (`2y3l` = 6단계).
- 연산자 두 번 = 커서 객체 하나 (`yy` `dd` `gcc`). 예외: `==`는 덩어리(객체 하나 정렬은 의미 없음), `gyy`는 Grasshopper 선택(마우스로 고른 것 포함).
- `j` / `k`는 범위가 아닙니다 (범위는 와이어를 따름).
- `d` 뒤 `i{n}` / `o{n}`은 와이어 끊기.
- **새 기능은 되도록 연산자나 범위로 얹습니다** (예: 2텀 `z{범위}`, 3텀 `gG{범위}`, 라벨 점프 뒤 연산자).

## 결과

- 연산자 5개 × 범위 7개가 새 키 없이 생깁니다. `.`([0011](0011-repeat.md))이 이 위에서 동작합니다.
- 범위 안 Relay는 같이 다루지만 단계로 세지 않습니다.

## 버린 대안

| 대안 | 버린 이유 |
|---|---|
| 기능마다 고유 키 | 조합이 안 됨, `.` 반복도 기능마다 따로 |
| 범위로 화면 방향(`Ctrl+hjkl`) | 데이터 흐름과 무관한 묶음이 됨 |
