# 0003. 문서를 바꾸는 명령은 모두 undo 기록 하나 (`u` 한 번)

- 상태: 채택 (2026-10-26, `.` 병합은 2026-11-09)
- 관련: `Formatter.cs`, `VimController.cs`, [자동 정렬 — 실행 취소](../formatting.md#실행-취소)

## 맥락

vim은 명령 하나를 `u` 하나로 되돌립니다. Grasshopper의 undo는 동작마다 기록이 따로 쌓여서, 정렬 한 번(이동 수십 개 + Relay 추가·삭제 + 와이어 변경)을 되돌리려면 `Ctrl+Z`를 여러 번 눌러야 합니다.

## 결정

- Engine에서 문서를 바꾸는 명령은 `doc.UndoUtil.RecordEvent`로 **기록 하나**에 모든 동작을 담습니다.
- 기록 안의 순서를 정해서 되돌리기·다시 하기 모두 맞게: 정렬은 Relay 추가 → 와이어 → 기존 Relay 삭제 → 이동.
- 바뀐 것이 없으면 기록을 남기지 않습니다 (이미 정렬된 화면에서 `==`).
- `u` / `Ctrl+r`은 Grasshopper의 undo / redo를 그대로 부릅니다. 비주얼 모드의 `u`만 예외로 선택 되돌리기입니다 ([0007](0007-visual-mode.md)).
- `.`으로 여러 명령을 되풀이하면 그 기록들을 `GH_UndoServer.MergeRecords(n)`으로 하나로 합칩니다 ([0011](0011-repeat.md)).

## 결과

- `u`와 `Ctrl+Z`가 같은 기록을 씁니다.
- 기록 순서는 Rhino에서 확인해야 합니다 ([검증 목록](../verification.md)).
- 새 기능을 만들 때 지켜야 할 규칙입니다 ([CLAUDE.md](../../CLAUDE.md#코드-규칙)).
