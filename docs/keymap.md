# 키맵

> 초안입니다. 키맵 설정 파일은 아직 없습니다 ([로드맵](roadmap.md)).

## 모드

- **Grasshopper 모드**: Grasshopper 기본 상태. 마우스로 조작합니다 (vim의 Insert 모드처럼 키가 원래 동작을 함).
- **Vim 모드**: 키보드로 조작합니다 (vim의 Normal 모드). 화면 좌하단에 `-- VIM(normal) --`이 표시됩니다.
- **비주얼 모드**: Vim 모드에서 `v`로 들어가 여러 객체를 고릅니다 (vim의 Visual 모드). `-- VIM(visual) --`이 표시됩니다.

```
Grasshopper 모드  ──`──▶  Vim 모드  ──v──▶  비주얼 모드
                  ◀──`──            ◀──v / Esc──
```

| 키 | 동작 |
|---|---|
| `` ` `` (백틱, `1` 왼쪽) | Vim 모드 켜기 / 끄기. 입력 중인 명령이나 비주얼 모드가 있어도 바로 나감 |
| `Esc` (Vim 모드에서) | 입력 중인 명령·고른 소스 취소 |

Grasshopper 모드의 `Esc`는 Grasshopper가 그대로 처리합니다.

### 다음 키 힌트

명령을 치다가(`g`, `y`, `d`, `gc`, `2`, `Space`, `o`, `i`, `gi` 등) 0.4초 동안 키를 누르지 않으면 모드 표시줄 위에 **다음에 누를 수 있는 키와 뜻**이 뜹니다 (nvim의 which-key). 다음 키를 누르거나 `Esc`, Vim 모드 나가기, 문서 바꾸기로 닫힙니다.

| 입력 중 | 힌트 |
|---|---|
| `g` | `=` `i{n}` `o{n}` `y` `c` `G` |
| `]` `[` | `e` `w` `s` `g` |
| `{n}` | `h` `j` `k` `l` `}` `{` `Ctrl+o` `Ctrl+i` `t` `/` `n` `N` `*` `#` `]` `[` `y` `=` `d` `z` `g` `.` `m` `'` `p` `P` (비주얼 모드는 이동과 마크만: `hjkl` `}` `{` `Ctrl+o` `Ctrl+i` `t` `/` `n` `N` `*` `#` `]` `[` `m` `'`) |
| `y` `=` `d` `gy` `gc` `z` `gG` | 두 번 누르기(`y`, `=`, `d`, `y`, `c`, `z`, `G`), `h` `l` `{n}h` `{n}l` `H` `L` `p` `t` `'`, `d`만 `i{n}` `o{n}`. 앞에 숫자가 있으면 실제 단계 수 (`2y` → `h` 상류 2단계) |
| `y2` 등 | `h` `l` (앞뒤 숫자를 곱한 단계 수), `p`, `t`, `'` |
| `Space` | `Space` |
| `m` | `a`~`z` (커서 객체에 마크 달기) |
| `'`, 연산자 뒤 `'` (`d'`) | 지금 문서에 설정된 마크와 그 객체 이름. 없으면 `설정된 마크 없음` |
| `o` `i` `I` `gi` `go` `di` `do` | 고를 수 있는 번호 범위. 숫자를 더 기다리는 중이면 다음 자리 번호, `Enter`, `Backspace` |

- `o{n}` / `i{n}` 직후(데이터 연산자 `f g s r n`을 받는 상태)에는 뜨지 않습니다. `o0 … 이동 … i1`처럼 평소에 머무는 상태라서입니다.
- `t` 다음(라벨을 기다리는 중)에도 뜨지 않습니다. 라벨이 캔버스에 그려지기 때문입니다.
- `Shift` 같은 수정키만 눌러서는 닫히지 않습니다 (`dH`의 `Shift`).
- 화면 좌표로 그려서 줌과 무관하게 같은 크기입니다.
- 힌트 표는 `KeyParserHints.cs` 한 곳에 있고, 테스트가 힌트의 키를 실제로 파서에 넣어 봅니다 (힌트와 문법이 어긋나지 않게).

Vim 모드에서는 캔버스의 한글 IME가 자동으로 꺼지고 모드를 나가면 복구됩니다 (찾기 `/` 입력줄이 열린 동안만 다시 켜짐). 아래 표에 있는 `Ctrl` 조합을 제외한 `Ctrl`/`Alt` 조합(`Ctrl+S`, `Ctrl+Z` 등)과 `Delete`, 방향키, PageUp/PageDown, F키는 Grasshopper가 그대로 처리합니다.

Vim 모드에서 Vimhopper가 가져가는 `Ctrl` 조합: `Ctrl+h` `Ctrl+j` `Ctrl+k` `Ctrl+l`, `Ctrl+r`, `Ctrl+o` `Ctrl+i`, `Ctrl+=` `Ctrl+-`. 이 중 Grasshopper의 `Ctrl+O`(파일 열기)는 Vim 모드에서 쓸 수 없으니 Grasshopper 모드에서 쓰거나 메뉴에서 엽니다.

## 이동

`hjkl`은 화면 위치가 아니라 **와이어 연결**을 따라 움직입니다. 기준이 자동 정렬과 같아서, **정렬된 화면에서는 그대로 좌 / 하 / 상 / 우**가 됩니다. 규칙과 설계 배경은 [이동 (hjkl)](navigation.md)을 참고하세요.

| 키 | 동작 |
|---|---|
| `h` | 부모로: 연결된 입력 중 맨 위 입력의 출처 (정렬하면 수평 와이어로 이어진 왼쪽 객체) |
| `l` | 자식으로: 나를 맨 위 입력으로 받는 자식 (정렬하면 수평 와이어로 이어진 오른쪽 객체). 없으면 가까운 층, 화면 위쪽 순 |
| `j` / `k` | 같은 층(정렬의 열) 안에서 아래 / 위. 덩어리 끝에서 계속 가면 다음 덩어리의 같은 층으로 |
| `{n}h` `{n}j` `{n}k` `{n}l` | vim처럼 n번 반복. 끝을 넘으면 끝에서 멈춤 (예: `3h`인데 부모가 두 단계뿐이면 두 단계) |
| `gi{n}` | 입력 n의 출처로 (입력 번호는 Vim 모드에서 화면에 표시됨) |
| `go{n}` | 출력 n을 받는 객체 중에서 `l`과 같은 규칙으로 |
| `Ctrl+h` `Ctrl+j` `Ctrl+k` `Ctrl+l` | 연결과 무관하게 화면상 좌 / 하 / 상 / 우로 가장 가까운 객체 (정렬하지 않은 화면에서) |
| `}` / `{` | 다음 / 이전 덩어리의 첫 객체로 (vim의 문단 이동, [덩어리 이동](#덩어리-이동)) |
| `{n}}` / `{n}{` | n개 건너뛴 덩어리로. 끝을 넘으면 끝 덩어리에서 멈춤 |
| `Ctrl+o` / `Ctrl+i` | 점프 목록에서 이전 / 다음 위치로. `{n}Ctrl+o`처럼 숫자를 붙이면 n개 ([점프 목록](#점프-목록)) |
| `t{라벨}` | 화면에 보이는 객체로 바로 ([라벨 점프](#라벨-점프)) |
| `/` `n` `N` `*` `#` | 이름으로 찾기, 같은 종류 찾기 ([찾기](#찾기)) |
| `m{a-z}` / `'{a-z}` | 커서 객체에 마크 달기 / 마크의 객체로 ([마크](#마크)) |

### 덩어리 이동

- 덩어리는 와이어로 이어진 객체들(`==`가 정렬하는 단위)이고, 연결이 없는 객체 하나도 덩어리 하나입니다.
- 순서는 `g=`가 쌓는 순서와 같습니다: 덩어리의 가장 위 객체의 위쪽 끝, 같으면 가장 왼쪽 객체의 왼쪽 끝. 정렬된 화면에서는 위에서 아래로입니다.
- 첫 객체는 덩어리의 가장 상류 층(정렬의 맨 왼쪽 열)에서 맨 위 객체입니다. 거기서 `j`로 같은 열을 내려갈 수 있습니다. Relay에는 내리지 않습니다.
- vim처럼 끝에서 처음으로 돌아가지 않습니다. 이미 끝 덩어리면 `다음 덩어리 없음` / `이전 덩어리 없음`이 표시됩니다.
- `{`는 지금 덩어리의 첫 객체가 아니라 이전 덩어리로 갑니다 (커서가 덩어리 중간에 있어도).

### 점프 목록

vim의 jumplist와 같은 방식입니다 (무엇을 점프로 치는지는 아래처럼 Vimhopper가 정함). 멀리 옮겨 가는 이동(점프)을 하면 떠난 자리가 목록에 남아서 `Ctrl+o`로 돌아가고 `Ctrl+i`로 다시 옵니다.

| 점프인 것 | 점프가 아닌 것 |
|---|---|
| `gi{n}`, `go{n}`, `{` / `}`, `t{라벨}`, `'{a-z}` | `h` `j` `k` `l` |
| 찾기 `/` `n` `N` `*` `#` | `/` 입력 중 미리 옮겨 보이는 것 |
| 숫자를 붙인 이동 (`3l`, `2j`) | `Ctrl+h` `Ctrl+j` `Ctrl+k` `Ctrl+l` |
| `Space Space`로 넣은 컴포넌트로 커서가 옮겨 갈 때 | `dd` 뒤 가까운 객체로 옮겨 가는 것 |
| `p` / `P`로 붙여넣은 객체로 커서가 옮겨 갈 때 | |

- 목록 끝에서 처음 `Ctrl+o`를 누르면 지금 위치도 저장되어 `Ctrl+i`로 돌아올 수 있습니다.
- 같은 객체는 목록에 한 번만 남습니다 (가장 최근 것). 최대 100개.
- `Ctrl+o`로 돌아간 뒤 새로 점프해도 뒤쪽 위치는 지워지지 않고, 떠난 자리가 끝에 붙습니다 (vim 기본).
- 지운 객체는 건너뛰고 숫자에도 세지 않습니다. `u`로 되살리면 다시 갈 수 있습니다.
- 다른 문서로 바꾸면 목록이 비워집니다. Vim 모드를 껐다 켜는 것으로는 비워지지 않습니다.
- 비주얼 모드에서도 커서를 옮기는 이동으로 씁니다.

### 라벨 점프

nvim의 flash·leap처럼 `t`를 누르면 화면에 보이는 객체마다 라벨이 뜨고, 라벨을 치면 그 객체로 커서가 옮겨 갑니다.

- 라벨은 중심이 화면 안에 있는 객체(커서 객체 제외)에 붙습니다. 객체 가운데에 분홍 바탕으로 그리고, 화면 좌표라 줌과 무관하게 같은 크기입니다.
- 커서(없으면 화면 중앙)에 가까운 객체부터 `a s d f g h j k l q w e r t y u i o p z x c v b n m` 순으로 한 글자 라벨을 받습니다.
- 26개보다 많으면 뒤쪽 글자를 두 글자 라벨의 첫 글자로 돌립니다 (`ma`, `ms` …). 한 글자 라벨은 두 글자 라벨의 앞부분이 되지 않아서, 한 글자 라벨은 치는 즉시 확정됩니다. 첫 글자를 치면 그 글자로 시작하지 않는 라벨은 사라지고 친 글자는 흐려집니다. `Backspace`로 첫 글자를 지웁니다.
- `Esc`나 라벨이 아닌 키는 라벨 점프를 그만두고 상태줄에 알립니다. 그 키는 다른 명령으로 쓰이지 않습니다. 고른 소스(`o{n}`)는 남습니다.
- 대소문자를 가리지 않고, 앞에 붙인 숫자는 무시합니다 (`3t` = `t`).
- 점프 목록에 기록됩니다. 비주얼 모드에서는 다른 이동처럼 선택 범위를 늘립니다.
- 데이터 연산자가 아니라서 `o0 t{라벨} i1`로 화면 저쪽 객체에 바로 연결합니다.
- 연산자 뒤에서는 범위입니다 ([연산자 + 범위](#연산자--범위)의 `t{라벨}`).
- vim의 `t{글자}`(그 글자 앞까지)와 키는 같고 뜻은 다릅니다 ([ADR 0019](adr/0019-label-jump-t.md)).

### 마크

vim의 `m` / `'`와 같습니다. 객체 하나에 글자 하나를 붙여 두고 어디서든 돌아옵니다.

- 마크는 **문서마다 따로**입니다. 다른 문서로 바꿨다 돌아와도 남고, 문서를 닫으면 버립니다. 파일에는 저장하지 않습니다.
- 같은 글자로 다시 달면 덮어씁니다. 글자는 `a`~`z`만 (대문자·숫자는 오류).
- `'{a-z}`는 점프라서 `Ctrl+o`로 돌아옵니다. 비주얼 모드에서는 선택이 그 객체까지 늘어납니다.
- 마크한 객체를 지우면 `'`가 `마크 a의 객체가 지워졌습니다`를 띄웁니다. `u`로 되살리면 다시 갑니다. 설정하지 않은 마크는 `마크 a가 없습니다`.
- 앞에 붙인 숫자는 무시합니다 (`3ma` = `ma`). 비주얼 모드에서도 같습니다 (`v3ma` = `vma`).
- 연산자 뒤 `'{a-z}`는 커서 객체에서 마크 객체까지의 블록입니다 (`y'a`, `d'a`, [연산자 + 범위](#연산자--범위)). 오류는 `'{a-z}`와 같습니다.
- 핫 리로드하면 마크가 지워집니다.

### 연결 강조

Vim 모드에서는 키를 누르지 않아도 커서 객체의 연결이 늘 강조됩니다. 와이어가 엉킨 화면에서 어디로 이어지는지 따라가기 위한 것입니다.

| 표시 | 뜻 |
|---|---|
| 파란 굵은 와이어 | 입력 와이어 (상류, 커서로 들어옴) |
| 자주색 굵은 와이어 | 출력 와이어 (하류, 커서에서 나감) |
| 파란 외곽선 + `h` 글자 (왼쪽 위) | 지금 `h`를 누르면 갈 객체 |
| 자주색 외곽선 + `l` 글자 (오른쪽 위) | 지금 `l`을 누르면 갈 객체 |

- 강조 와이어는 Grasshopper가 그리는 것과 같은 곡선(`GH_Painter.ConnectionPath`)을 일반 와이어 위, 객체 아래에 다시 그립니다.
- 와이어 표시를 숨김(Hidden)이나 흐림(Faint)으로 둔 입력도 커서에 있으면 **일반 와이어와 같은 굵기·진하기로** 강조합니다 (의도한 동작). 평소엔 숨겨 둔 연결도 커서를 올리면 어디로 가는지 보이게 하려는 것입니다.
- `h` / `l` 표시는 이동과 같은 코드(`GraphNavigator.Hops` → `Move`)로 정하므로 실제 이동과 어긋나지 않습니다. 자식을 드래그해서 순서가 바뀌면 `l` 표시도 바로 따라갑니다. 표시가 없으면 그 방향으로는 갈 곳이 없습니다 (`부모 없음` / `자식 없음`).
- Relay는 커서와 바로 이어진 와이어까지만 강조합니다 (Relay 너머는 강조하지 않음).
- 비용: 와이어는 매 프레임 커서의 파라미터만 훑고, `h` / `l` 대상은 커서가 바뀌거나 문서가 바뀔 때(undo 기록, 객체 추가·삭제)만 다시 계산합니다. 커서 자식들의 위치도 매 프레임 비교합니다 (커서 차수만큼).

## 데이터 모양

| 키 | 동작 |
|---|---|
| `K` | 커서 객체의 입력·출력 데이터 모양 패널 (vim의 hover) |

- 패널은 커서 객체 옆에 화면 좌표로 뜹니다 (힌트 패널과 같은 모양). 파라미터마다 접근(item/list/tree)과 데이터 연산자, 가지 수, 항목 수, null 수, 항목 타입, 가지별 항목 수(셋 넘으면 `{0;0} 10, {0;1} 10 … 가지마다 10개` / `… 가지당 3~10개`).
- `K`를 누른 때의 값입니다. 다음 키에 닫히고 그 키는 그대로 처리됩니다. `K`와 `Esc`는 닫기만 합니다. 커서가 옮겨 가거나 Vim 모드를 나가거나 문서가 바뀌어도 닫힙니다.
- 짝 맞춤 힌트(오류 아님): 항목 접근(item) 입력 중 비어 있지 않은 것끼리 longest list로 비교합니다. 모두 항목 1개면 힌트 없음. 가지가 적으면 `B: 가지 3개 vs A 10개 → B의 마지막 가지가 7번 반복`, 항목이 적으면 `B: 항목 3개 vs A 10개 → …`, 항목 1개면 `B: 항목 1개가 100번 재사용`. 리스트·트리 입력은 비교하지 않고, 리스트 입력의 가지 수만 재사용 횟수에 넣습니다.
- 계산 전(`아직 계산되지 않았습니다`), 꺼진 객체, 파라미터가 없는 객체는 상태줄에 알립니다.
- 숫자는 무시합니다 (`3K` = `K`). 점프가 아니고 undo·`.`에 남지 않습니다. 비주얼 `K`(`{n}K` 포함)는 비어 있어 아무것도 하지 않습니다.

## 찾기

vim의 `/`, `n`, `*`와 같습니다. 무엇을 어떤 순서로 찾는지는 [0020](adr/0020-search.md).

| 키 | 동작 |
|---|---|
| `/` | 찾기 입력줄 (모드 표시줄 자리). 글자를 치면서 맞는 객체가 노란 테두리, 다음 대상이 주황 테두리로 보이고 커서가 미리 옮겨 감 (vim의 incsearch) |
| `/` 입력줄의 `Enter` | 커서 다음의 맞는 객체로 점프. 빈 `Enter`는 마지막 찾기를 다시 |
| `/` 입력줄의 `Esc` | 취소. 커서와 화면이 `/` 누르기 전으로 돌아감 |
| `/` 입력줄의 `Backspace` / `Ctrl+u` / `Ctrl+v` | 한 글자 지우기 (빈 줄이면 취소) / 모두 지우기 / 클립보드 첫 줄 붙여넣기 |
| `{n}/` | Enter 때 n번째 맞는 객체로 |
| `n` / `N` | 마지막 찾기를 같은 / 반대 방향으로. `{n}n`은 n번 |
| `*` / `#` | 커서 객체와 같은 컴포넌트 종류의 다음 / 이전 객체로. `{n}*`은 n번. 마지막 찾기가 되어 `n`이 되풀이 (`#`이면 `n`이 뒤로) |

- 맞는 것: 별명(NickName), 이름(Name, 예: Addition), 탭·묶음 이름(예: Maths, Operators) 중 하나에 글자가 들어 있으면. 대소문자는 무시합니다. 그룹·스크리블은 찾지 않습니다.
- 순서: 덩어리 순서(`{` / `}`와 같음) → 덩어리 안에서 정렬의 열(왼쪽부터) → 위→아래. 정렬된 화면에서는 덩어리마다 왼쪽 열부터 읽어 내려가는 순서입니다.
- 끝을 넘으면 처음부터 이어 가고 상태줄에 `search hit BOTTOM, continuing at TOP` (뒤로면 `TOP` → `BOTTOM`). 상태줄에는 늘 `[3/12] /abc`처럼 몇 번째인지가 보입니다. 맞는 것이 없으면 `찾을 수 없습니다: /abc`.
- 찾기로 옮겨 가는 것은 모두 점프입니다 (`Ctrl+o`로 돌아옴). 비주얼 모드에서는 선택이 찾은 객체까지 늘어나고 `u`로 되돌립니다.
- 원격 연결: `o0` → `/이름` `Enter` → `i1`. 찾기로 멀리 가서 연결합니다 (고른 소스는 남음). `Enter` 뒤에는 `n`이 다시 찾기라서 `o0` → `/이름` `Enter` → `n` → `i1`도 됩니다.
- `o{n}` 바로 뒤의 `n`은 Invert입니다 ([데이터 연산자](#데이터-연산자)). 맞는 객체를 `n`으로 넘겨 가며 소스를 고르려면 먼저 찾고(`/이름` `Enter`, `n` …) 그다음 `o{n}`을 고릅니다.
- 입력줄이 열린 동안 `` ` ``를 누르면 찾기를 버리고(커서는 미리 옮겨 간 자리) Vim 모드를 나갑니다. 다른 키(`Ctrl+S` `Ctrl+Z` 포함)는 입력줄이 받고 Grasshopper로 가지 않습니다.
- 입력줄에서는 **한글을 칠 수 있습니다**. 입력줄이 열린 동안만 캔버스 IME를 다시 켜고(한/영 상태는 그 전 그대로), 조합 중인 글자는 주황 밑줄로 보입니다. 닫으면 다시 끕니다.
- 강조는 입력하는 동안만입니다 (vim의 `hlsearch`처럼 남지는 않음).
- 아직 없는 것: 연산자 + `/` 범위(`d/abc`), `?` 뒤로 찾기, 입력줄 안 커서 이동·찾기 기록. 입력줄은 4텀 `:` 명령줄이 같이 씁니다.

## 다음·이전 (`]` / `[`)

`]` / `[` 다음에 글자 하나 ([0022](adr/0022-diagnostics-keys.md)). 숫자를 받고(`3]e`), 점프 목록에 기록하고, 비주얼 모드에서는 선택을 늘립니다. 다른 글자는 오류, `Esc`는 취소. 키를 누를 때 문서에서 메시지·계산 시간을 읽습니다.

| 키 | 동작 |
|---|---|
| `]e` / `[e` | 다음 / 이전 **오류 원인**. 상태줄 `오류 원인 2/3 (오류 12개)   이름: 첫 메시지` |
| `]w` / `[w` | 다음 / 이전 **경고 원인**. 상태줄 `경고 원인 1/4 (경고 9개)   …` |
| `]s` / `[s` | 느린 순 순위에서 커서 객체의 다음(한 단계 빠른 객체) / 이전(한 단계 느린 객체). 커서 객체에 시간이 없으면(순위에 없음) `]s`는 가장 느린 객체, `[s`는 가장 빠른 객체로. 상태줄 `느린 객체 1/37 12 ms 이름` |
| `]g` / `[g` | 다음 / 이전 그룹의 **첫 멤버**(문서 순서로 처음 오는 객체). 상태줄 `그룹 2/5 이름` |

- **원인 규칙**: 가장 높은 메시지 등급이 오류인 객체 중, 상류(입력 와이어를 거슬러 끝까지, Relay 포함)에 오류 객체가 없는 것. 경고는 등급이 경고인 객체 중 상류에 경고나 오류 객체가 없는 것. 번진 메시지는 건너뜁니다.
- **순서**: `e` `w` `g`는 찾기와 같은 문서 순서(덩어리 → 열 → 위→아래, [0020](adr/0020-search.md)), `s`는 느린 순. 끝을 넘으면 찾기처럼 반대쪽 끝에서 이어가고 `search hit BOTTOM, continuing at TOP`을 붙입니다.
- `]g`가 그룹 객체가 아니라 첫 멤버로 가는 것은 hjkl이 멤버 위에서 동작하기 때문입니다. 첫 멤버가 같은 그룹(중첩·겹친 그룹)은 하나로 치고, 상태줄에는 멤버가 적은 그룹(안쪽 그룹) 이름이 보입니다. 컴포넌트·파라미터가 없는 그룹은 건너뜁니다.
- Vim 모드인 동안 가장 느린 객체 5개의 오른쪽 위에 계산 시간(`12 ms`)이 보라 바탕으로 그려집니다. 시간이 0인 객체는 빠집니다.
- 대상이 없으면 `오류 없음` / `경고 없음` / `계산 시간이 기록된 객체 없음` / `그룹 없음`.

## 화면

| 키 | 동작 |
|---|---|
| `Ctrl+=` / `Ctrl+-` | 커서 객체를 기준으로 확대 / 축소 (커서가 화면에서 제자리에 머묾) |
| `zz` | 커서 객체를 화면 가운데로 |
| `z{범위}` | 범위를 화면에 맞춤 (예: `zL` 하류 전체, `z2h` 상류 2단계, `zp` 덩어리. [연산자 + 범위](#연산자--범위)) |
| 비주얼 `z` | 선택한 객체들을 화면에 맞춤. 비주얼 모드에 머묾 |

선택이 바뀌어도 화면은 객체가 가장자리 여백 밖으로 나갈 때만 필요한 만큼 움직입니다 (vim의 `scrolloff`).

- `z`는 접두어입니다. 한 번만 누르면 범위를 기다립니다 ([0014](adr/0014-zoom-prefix.md)).
- 화면에 맞출 때는 범위를 감싸는 직사각형을 가운데에 두고 가장자리에 40픽셀 여백을 남깁니다.
  - 지금 배율로 들어가지 않으면 들어갈 때까지 축소합니다 (최소 10%).
  - 들어가면 100%까지만 확대하고, 지금 배율보다 줄이지는 않습니다. 300%에서 작은 범위에 `zp` 하면 가운데로만 옮깁니다.
- `Ctrl+=` / `Ctrl+-`는 한 번에 1.25배. 커서 객체가 화면에서 제자리에 머물고, 가장자리 근처여도 화면을 밀지 않습니다. 커서가 없거나 화면 밖이면 화면 가운데를 기준으로 하고, 그래도 커서가 안 보이면 커서로 화면을 옮깁니다. 배율은 10%..500%.
- 줌은 문서를 바꾸지 않으므로 undo에 남지 않고, `.` 되풀이 대상도, 점프도 아닙니다.
- 비주얼 `z`는 선택을 바꾸지 않으므로 비주얼 모드를 나가지 않습니다 (맞춰 보고 선택을 이어 다듬을 수 있게).

## 정렬

| 키 | 동작 |
|---|---|
| `==` | 선택 객체와 와이어로 이어진 덩어리만 자동 정렬 (vim의 `==`가 현재 줄만 정렬하듯) |
| `g=` | 문서 전체 자동 정렬. 덩어리마다 따로 정렬하고 서로 겹치면 아래로 밂 |
| `={범위}` | 범위만 정렬 (예: `=L` 하류, `=2h` 상류 2단계. [연산자 + 범위](#연산자--범위)) |

- 덩어리의 왼쪽 위 모서리는 제자리에 남습니다. 이미 정렬된 배치를 다시 정렬해도 움직이지 않습니다.
- Relay를 알아서 넣고 뺍니다. 사용자가 넣은 Relay도 다시 계산합니다.
- 객체 이동, Relay 추가·삭제, 와이어 변경을 `u`(또는 `Ctrl+Z`) 한 번으로 되돌립니다.
- `==`는 덩어리 밖 객체를 옮기지 않으므로, 덩어리가 커지면 주변 객체와 겹칠 수 있습니다.
- Vim 모드에서 `Space`는 리더 키입니다. 컴포넌트 검색은 `Space Space`로 엽니다 ([넣기](#넣기)).

규칙은 [자동 정렬](formatting.md)을 참고하세요.

## 연결

| 키 | 동작 |
|---|---|
| `o{n}` | 선택된 객체의 출력[n]을 소스로 고름 (주황색 원으로 표시) |
| `i{n}` | 고른 소스를 선택된 객체의 입력[n]에 연결, 기존 와이어는 교체 |
| `I{n}` | 기존 와이어를 유지하고 추가로 연결 (Shift+드래그와 같음) |
| `u` / `Ctrl+r` | 실행 취소 / 다시 실행 (Grasshopper의 `Ctrl+Z` / `Ctrl+Y`와 같음) |

- 인덱스는 **0부터** 시작합니다. Vim 모드에서는 선택된 객체의 입출력 옆에 번호가 표시됩니다.
- 파라미터가 10개 이하면 한 자리 숫자를 누르는 즉시 확정됩니다. 11개 이상이면 숫자를 더 붙일 수 없을 때 확정되고, 그 전에는 다음 키나 `Enter`로 확정합니다. 예를 들어 출력이 15개이면 `o2`는 즉시 확정, `o1`은 `o12`가 될 수 있으므로 다음 키를 기다립니다.
- 소스는 연결 후 해제됩니다.

## 넣기

| 키 | 동작 |
|---|---|
| `Space Space` | 커서 객체 오른쪽에 Grasshopper 컴포넌트 검색창을 띄움. 놓인 컴포넌트로 커서가 옮겨 감 |
| `p` / `P` | Grasshopper 클립보드(`y`, `Ctrl+C`로 복사한 것)를 커서 객체 오른쪽 / 왼쪽에 붙여넣음 ([붙여넣기](#붙여넣기)) |

- Vim 모드에서 `Space`는 리더 키입니다. Grasshopper 모드(`` ` ``로 나간 상태)의 `Space`는 원래대로 마우스 위치에 검색창을 띄웁니다.
- `o{n}`으로 출력을 골라 둔 채 넣으면, 놓인 컴포넌트에서 바로 `i{n}`으로 연결할 수 있습니다: `o0  Space Space  (검색해서 넣기)  i0`
- 검색창을 닫고(`Esc`) 캔버스에서 다른 키를 누르면 더 기다리지 않습니다.
- `Space` 다음의 다른 키는 아직 비어 있습니다 (키맵 설정 파일의 사용자 매핑용).

## 데이터 연산자

`o{n}` 또는 `i{n}` 바로 뒤에 붙이면 방금 고른 파라미터에 적용되고 여러 개를 이어 붙일 수 있습니다. 같은 연산자를 다시 적용하면 꺼집니다.

| 키 | 연산 |
|---|---|
| `f` | Flatten |
| `g` | Graft |
| `s` | Simplify |
| `r` | Reverse |
| `n` | Invert (Boolean 파라미터만) |

`o{n}` / `i{n}` 바로 뒤의 `n`은 찾기 되풀이가 아니라 Invert입니다 (기존 문법이 이김). 찾기를 되풀이하려면 다른 키(이동 등)를 먼저 누릅니다.

## 비주얼 모드

| 키 | 동작 |
|---|---|
| `v` | 비주얼 모드 시작. 지금 객체가 시작점이 됨 |
| 이동 키 (`hjkl`, `{n}h`, `gi{n}`, `{` / `}`, `Ctrl+hjkl`, `Ctrl+o` / `Ctrl+i` 등) | 커서를 옮기며 선택 범위를 늘리거나 줄임 |
| `t{라벨}` | 라벨 객체로 커서를 옮겨 시작점과의 블록을 선택 ([라벨 점프](#라벨-점프)) |
| `/` `n` `N` `*` `#` | 찾은 객체로 커서를 옮겨 선택을 늘림 ([찾기](#찾기)) |
| `o` | 시작점과 커서를 맞바꿈 (반대쪽 끝을 조정할 때) |
| `H` / `L` | 지금 선택된 객체들의 상류 / 하류 전체를 선택에 더함. 커서를 옮겨도 남음 |
| `u` | 선택을 한 단계 전으로 되돌림 (커서 이동, `o`, `H`/`L` 모두). 비주얼 모드에서는 실행 취소가 아님 |
| `y` | 선택한 객체를 복사하고 비주얼 모드 종료 (`Ctrl+V`로 붙여넣기) |
| `gy` | 선택한 객체의 참조(파일 경로와 GUID)를 복사하고 비주얼 모드 종료 |
| `=` | 선택한 객체만 자동 정렬하고 비주얼 모드 종료. 덩어리가 여럿이면 `g=`처럼 따로 정렬 |
| `d` | 선택한 객체를 삭제하고 비주얼 모드 종료 |
| `gc` | 선택한 객체를 켜고 끄고 비주얼 모드 종료 |
| `gG` | 선택한 객체를 그룹으로 묶고 비주얼 모드 종료. 이름은 입력줄로 ([연산자 + 범위](#연산자--범위)) |
| `z` | 선택한 객체를 화면에 맞춤. 비주얼 모드는 그대로 ([화면](#화면)) |
| `Ctrl+=` / `Ctrl+-` | 확대 / 축소. 비주얼 모드는 그대로 |
| `g=` | 문서 전체 정렬하고 비주얼 모드 종료 |
| `Space Space` | 컴포넌트 검색창을 열고 비주얼 모드 종료 |
| `m{a-z}` | 커서 객체에 마크 달기 (비주얼 모드 유지, 숫자 무시) |
| `'{a-z}` | 마크의 객체로 커서를 옮겨 선택을 늘림 (숫자 무시) |
| `v` / `Esc` | 비주얼 모드 종료. 커서 객체 하나만 남음 |

- vim처럼 범위는 **시작점과 커서 두 끝으로만** 정해지고 지나온 경로와는 무관합니다. 두 끝 객체를 감싸는 직사각형 안에 중심이 들어오는 객체가 선택되므로, 정렬된 화면에서는 열과 행으로 된 블록이 됩니다.
- 커서를 되돌리면 범위도 줄어듭니다. 다만 `h`/`l`은 서로의 역이 아니어서(`l`로 간 자식의 맨 위 입력이 원래 객체가 아닐 수 있음) `l` 다음 `h`가 제자리가 아닐 수 있습니다. 지나온 선택으로 정확히 돌아가려면 `u`를 씁니다. `H`/`L`로 더한 객체도 `u`로만 뺄 수 있습니다.
- `i`/`I`(연결)는 비주얼 모드에서 쓸 수 없습니다. `o`는 출력 고르기가 아니라 양 끝 바꾸기입니다.
- 범위로 표현하기 어려운 흩어진 객체는 Grasshopper 모드에서 Ctrl+클릭으로 고른 뒤 `` ` `` → `gyy` 합니다.

## 연산자 + 범위

vim의 `dw`처럼 연산자 뒤에 범위를 붙입니다. 범위는 이동과 같은 `h`(상류 쪽) / `l`(하류 쪽)이고, 커서 객체도 범위에 들어갑니다.

| 키 | 범위 |
|---|---|
| `{연산자}h` / `{연산자}l` | 상류 / 하류로 한 단계 |
| `{연산자}{n}h` / `{연산자}{n}l` | 상류 / 하류로 n단계 |
| `{연산자}H` / `{연산자}L` | 상류 / 하류 전체 (원뿔 모양) |
| `{연산자}p` | 커서 객체가 속한 덩어리 전체 (vim의 문단). `=p`는 `==`와 같음 |
| `{연산자}t{라벨}` | 커서 객체와 라벨 객체를 두 끝으로 하는 블록 (비주얼 모드의 `v t{라벨}`과 같은 범위, 숫자 무시) |
| `{연산자}'{a-z}` | 커서 객체와 마크 객체를 두 끝으로 하는 블록 (`t{라벨}`과 같은 범위, 숫자 무시). 마크가 없거나 그 객체가 지워졌으면 오류 |

| 연산자 | 동작 |
|---|---|
| `y` | 범위를 복사 (예: `yL` 하류 전체, `y2h` 상류 2단계, `y'a` 마크 a까지) |
| `=` | 범위만 자동 정렬 (예: `=H` 상류만 정렬) |
| `d` | 범위를 삭제 (예: `dL` 하류 전체 삭제, `d'a` 마크 a까지 삭제) |
| `gy` | 범위의 참조(파일 경로와 GUID)를 복사 (예: `gyL` 하류 전체의 참조) |
| `gc` | 범위를 켜고 끄기 (Grasshopper의 Enable/Disable, 예: `gcH` 상류 전체 끄기) |
| `z` | 범위를 화면에 맞춤 (예: `zL` 하류 전체 보기, `zp` 덩어리 보기). `zz`는 커서 객체를 가운데로 |
| `gG` | 범위를 Grasshopper 그룹으로 묶고 이름을 붙임 (예: `gGp` 덩어리, `gGH` 상류 전체, `gG'a` 마크 a까지). `gGG`는 커서 객체 하나 |

- 이동 `h`/`l`은 맨 위 입력 와이어 하나만 따라가지만, 범위는 **모든 입력·출력 와이어**를 따라갑니다. 그래서 `yh`는 커서 객체와 그 입력에 연결된 객체 전부입니다.
- 숫자는 vim처럼 연산자 앞에도 붙일 수 있고, 앞뒤 숫자는 곱합니다 (`2yl` = `y2l`, `2y3l` = 6단계).
- `p`는 단계가 없어서 앞뒤 숫자를 무시합니다 (`3yp` = `y3p` = `yp`). 와이어 방향과 무관하게 이어진 객체 전부이고, Relay도 들어갑니다.
- 비주얼 모드의 `p`는 범위가 아닙니다 (비주얼 모드의 연산자는 범위 없이 바로 실행되므로). 지금은 비어 있습니다.
- 범위 안의 Relay는 같이 복사·정렬되지만 단계로 세지 않습니다 (정렬에서 풀리는 Relay이므로).
- 범위는 와이어를 따라가므로 `j`/`k`는 범위가 될 수 없습니다. 화면 위치로 고르는 범위는 `t{라벨}` / `'{a-z}` 블록뿐입니다.
- `=t{라벨}`, `='a`는 비주얼 `=`처럼 블록 안 덩어리를 따로 정렬합니다.
- 연산자를 두 번 누르면(`yy`, `dd`, `gcc`) 커서 객체 하나입니다. 예외는 둘입니다: `==`는 덩어리(객체 하나만 정렬하는 것은 의미가 없으므로), `gyy`는 지금 Grasshopper에서 선택된 객체들(마우스로 고른 것도 포함하려고). 앞에 붙인 숫자는 무시합니다.
- `gy`, `gc`, `gG` 앞에도 숫자를 붙일 수 있습니다 (`2gcl` = `gc2l`).
- `gc`는 켜진 것과 꺼진 것이 섞여 있으면 하나라도 켜져 있을 때 모두 끄고, 모두 꺼져 있을 때 모두 켭니다.
- `d`, `gc`도 `u` 한 번에 모두 되돌아갑니다. 삭제한 객체로 연결되어 있던 남은 객체의 와이어도 함께 돌아옵니다.
- `gG`는 객체를 고른 뒤 모드 표시줄 자리에 `그룹 이름: ` 입력줄을 엽니다 (`/`와 같은 입력줄, 한글 됨). 묶일 객체는 초록 점선 테두리. `Enter`로 그 이름(빈 이름도 됨)의 그룹을 만들고, `Esc`나 빈 줄에서 `Backspace`는 아무것도 바꾸지 않습니다. 색은 Grasshopper 기본 그룹 색입니다.
- 이미 다른 그룹에 든 객체도 새 그룹에 함께 들어갑니다 (원래 그룹에서 빠지지 않음, Grasshopper의 겹친 그룹). 범위 안의 Relay도 들어갑니다. `u` 한 번에 그룹이 없어집니다.

### 와이어 끊기

| 키 | 동작 |
|---|---|
| `di{n}` | 입력 n에 들어오는 와이어를 모두 끊기 |
| `do{n}` | 출력 n에서 나가는 와이어를 모두 끊기 |

`i` = 입력, `o` = 출력은 연결(`i{n}` / `o{n}`)과 같은 뜻입니다.

## 되풀이

| 키 | 동작 |
|---|---|
| `.` | 마지막 변경을 **지금 커서 객체에서** 다시 실행 (vim의 `.`) |
| `{n}.` | 숫자 단계 범위면 단계 수를 n으로 바꿔서 (`d2l` 뒤 `3.` = `d3l`). 이후의 `.`도 n단계 |

| 되풀이되는 변경 | 되풀이되지 않음 |
|---|---|
| `d` `=` `gc` + 범위 (`'{a-z}` 포함), `dd`, `gcc`, 이름을 확정한 `gG` + 범위 / `gGG`, `==`, `g=`, `di{n}` / `do{n}`, `i{n}` / `I{n}`, 데이터 연산자, `p` / `P` | 이동, 줌(`z`, `Ctrl+=`), `m` / `'` 마크, `y`·`gy` 복사, `t{라벨}` 범위 (`dt{라벨}` 등), `u` / `Ctrl+r`, `v` 등 비주얼 모드 조작, `o{n}`만 고르기, `Space Space`, 오류 (실행했지만 바뀐 것이 없는 경우 포함: 소스 없이 `i{n}`, 커서 객체 없이 `dd`, 와이어 없는 `di{n}` 등) |

- `t{라벨}` 범위는 화면마다 라벨이 달라서 되풀이하지 않습니다. `dt{라벨}` 뒤 `.`은 그 전의 변경을 되풀이합니다.
- `'{a-z}` 범위는 같은 마크 글자로 되풀이합니다. 마크는 `.` 할 때 다시 찾으므로 `gc'a` 뒤 다른 객체에서 `.`은 거기서 마크 a까지입니다. `d'a` 뒤 `.`은 마크 객체가 지워졌으므로 오류입니다 (`ma`로 다시 달면 됨).
- `H`/`L`/`p` 범위와 범위 없는 명령(`dd`, `di1` 등)은 숫자를 무시합니다 (`dp` 뒤 `3.`도 `dp`).
- `p` 뒤 `.`은 지금 커서 객체 옆에 다시 붙여넣습니다. 붙여넣으면 커서가 놓인 객체로 가므로 `p..`는 오른쪽으로 이어 붙입니다.
- `gG` 뒤 `.`은 지금 커서에서 같은 범위를 **같은 이름으로 묻지 않고** 묶습니다 (vim의 `.`이 넣은 글을 되풀이하듯). `{n}.`은 단계 수를 바꿉니다. 이름 입력을 `Esc`로 취소하면 변경이 아니므로 그 전의 변경이 남습니다. `gGt{라벨}`은 다른 범위처럼 되풀이하지 않습니다.
- 비주얼 모드에서 한 변경은 커서 객체 형태로 되풀이합니다: 비주얼 `d` → `dd`, `gc` → `gcc`, `gG` → `gGG`, `=` → `==`. 비주얼 모드 안에서는 `.`을 쓸 수 없습니다.
- 데이터 연산자는 앞의 `o{n}` / `i{n}`과 묶어서 되풀이합니다. `o1f` 뒤 `.`은 지금 객체의 출력[1]을 flatten하고 고른 소스는 바꾸지 않습니다.
- `i{n}`(`I{n}`) 뒤 `.`은 같은 입력 번호에 **지금 고른 소스**(`o{n}`)를 연결합니다. 소스는 연결하면 해제되므로, 같은 출력을 여러 곳에 이으려면 `o{n}`을 다시 고른 뒤 `.` 합니다. 고른 소스가 없으면 오류이고 뒤의 데이터 연산자도 적용하지 않습니다.
- 지금 객체에 그 번호의 입력·출력이 없으면 오류입니다.
- `u` 한 번에 `.` 한 번이 되돌아갑니다. `i0f`, `o0fg`처럼 여러 명령으로 된 변경도 `.`으로 되풀이한 것은 한 번에 되돌아갑니다 (처음 입력한 `i0f`는 명령마다 한 번씩).

## 복사

| 키 | 동작 |
|---|---|
| `yy` | 커서 객체를 복사 (Grasshopper의 `Ctrl+C`와 같음, `p` 또는 `Ctrl+V`로 붙여넣기) |
| `y{범위}` | 범위를 복사 ([연산자 + 범위](#연산자--범위)) |
| `gyy` | Grasshopper에서 선택된 객체들의 참조(파일 경로와 GUID)를 텍스트로 복사 |
| `gy{범위}` | 범위의 참조를 복사 (`gyL`, `gy2h`) |

vim에서 같은 키를 두 번 누르면(`yy`, `==`) 현재 줄이 범위이듯, `yy`는 커서 객체 하나를 복사합니다. 여러 개는 범위(`yL`)나 비주얼 모드의 `y`로 복사합니다.

`y`는 캔버스에 붙여넣을 객체 자체(Grasshopper 클립보드 형식, XML)를, `gy`는 객체를 가리키는 텍스트를 복사합니다. `gy`는 에디터의 `파일:줄`처럼 `파일 경로:InstanceGuid`를 복사합니다. 여러 개면 경로는 한 번만 쓰고 GUID를 쉼표로 잇습니다.

```
D:/work/bridge.ghx:3f2a9c1e-4bb5-406c-a527-4dfb6f990136
D:/work/bridge.ghx:3f2a9c1e-4bb5-406c-a527-4dfb6f990136,8b07d4f2-0c1d-4e2a-9f3b-1a2b3c4d5e6f
```

- `InstanceGuid`는 문서 안에서 유일해서 `.ghx`에서 이 값으로 객체를 바로 찾을 수 있습니다. `.gh`는 바이너리라 검색할 수 없으니 `.ghx`로 저장해 두는 것이 좋습니다. 새로 놓은 객체는 저장해야 파일에 들어갑니다.
- 저장한 적 없는 문서는 GUID만 복사합니다.
- 마우스로 여러 개를 고르고 `` ` `` → `gyy` 하면 모두 복사됩니다. 왼쪽 열부터, 같은 열은 위에서부터 나열합니다.

## 붙여넣기

| 키 | 동작 |
|---|---|
| `p` | 클립보드의 객체들을 커서 객체 오른쪽에 (`Space Space` 검색창 자리) |
| `P` | 커서 객체 왼쪽에 |

- 붙여넣는 객체끼리의 배치와 그 사이 와이어는 Grasshopper의 `Ctrl+V`처럼 그대로입니다. 클립보드 밖 객체에서 오던 입력 와이어도 그 객체가 문서에 있으면 다시 이어집니다 (Grasshopper와 같음).
- 묶음의 왼쪽 끝(`P`는 오른쪽 끝)이 커서 객체에서 60만큼 떨어지고, 세로는 첫 객체의 가운데가 커서 객체의 가운데에 맞춰집니다. 커서 객체가 없으면 화면 가운데에.
- 커서는 붙여넣은 객체 중 첫 객체(`gyy` 순서: 왼쪽 열부터, 같은 열은 위에서부터)로 옮겨 가고, 점프로 기록됩니다.
- 마우스 위치는 쓰지 않습니다. `u` 한 번에 모두 되돌아갑니다. `.`으로 되풀이합니다.
- 숫자는 무시합니다 (`3p` = `p`). 같은 묶음을 여러 개 놓으려면 `p..`.
- 클립보드가 비었거나 Grasshopper 객체가 아니면 `클립보드에 Grasshopper 객체가 없습니다`.
- 비주얼 모드의 `p` / `P`는 비어 있습니다. 연산자 뒤 `p`는 지금처럼 덩어리 범위입니다 (`yp`).
