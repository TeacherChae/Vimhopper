# vim에서 더 가져올 것 (제안)

> 검토용 제안 문서입니다. 비주얼 모드(`v`)와 복사(`yy`, 비주얼 `y`, `gy`)는 구현되었고([키맵](keymap.md)), 나머지는 아직 정한 것이 없습니다. 이동(hjkl), 와이어 연결(`o{n}` → `i{n}`), 데이터 연산자, 자동 정렬(`==` / `g=`)이 잘 동작한다는 전제에서, 그 위에 붙일 만한 vim(nvim)의 장점을 Grasshopper에서 불편한 지점과 연결해 정리했습니다.

## 1. 문법: 연산자 + 범위

vim의 진짜 힘은 키 개수가 아니라 **동사(`d` `y` `c` `=`)와 범위(모션)를 자유롭게 조합**하는 데 있습니다. 자동 정렬을 `==`로 정하면서 `=`를 연산자 자리로 남겨 두었습니다.

범위는 새 문법을 만들지 않고 **이미 익힌 hjkl 모션을 그대로** 씁니다. h가 부모 쪽, l이 자식 쪽이므로 범위도 같은 방향으로 읽힙니다.

| 범위 | Grasshopper에서의 의미 |
|---|---|
| `h` / `2h` | 상류 쪽으로 1 / 2단계까지 |
| `l` / `3l` | 하류 쪽으로 1 / 3단계까지 |
| `H` / `L` | **상류 전체 / 하류 전체** (원뿔 모양 선택). 대문자 = 끝까지 |
| 연산자 두 번 (`dd`, `yy`) | 커서 객체 하나. vim에서 두 번 누르면 가장 작은 단위(한 줄)인 것과 같음. `==`만 예외로 덩어리 (아래 참고) |
| `i{n}` / `o{n}` | 입력 n번 / 출력 n번에 걸린 **와이어** |

조합 예:

```
dH    상류를 통째로 삭제
yL    하류를 복사
=H    상류만 정렬
d2h   상류 2단계까지 삭제
dd    커서 객체 삭제
yy    커서 객체 복사 (구현됨)
di0   입력 0번의 와이어 끊기
do1   출력 1번의 와이어 모두 끊기
vL    하류를 선택 (비주얼 모드)
```

상류 원뿔 선택은 Grasshopper에서 손으로 하기 가장 귀찮은 작업 중 하나입니다. 클러스터로 묶거나, 일부를 떼어 다른 파일로 옮길 때 매번 필요합니다.

**vim의 `i`/`a` 텍스트 객체(`iw`, `ap`)는 들여오지 않습니다.**

- Vimhopper에서 `i`는 이미 "입력"(`i{n}` 연결)입니다. 연산자 뒤에서 `i`가 "inner"가 되면 `di0`(입력 0 끊기)과 `diu`(상류 삭제)처럼 같은 자리의 `i`가 두 뜻이 됩니다. 파서는 다음 글자로 구분할 수 있어도 사람에게는 헷갈립니다.
- inner/around 구분 자체가 Grasshopper에서는 거의 의미가 없습니다. "상류의 바깥쪽" 같은 것이 없기 때문입니다.
- 그래서 `i` = 입력, `o` = 출력으로 연산자 앞뒤 어디서나 같은 뜻을 유지합니다. 예외는 비주얼 모드의 `o`로, vim과 같이 선택의 양 끝을 바꿉니다 (비주얼 모드에서는 연결을 하지 않으므로).

**남은 검토거리**

- 그룹: 안쪽(그룹 안 객체만)과 바깥쪽(그룹 자체까지)이 실제로 다른 유일한 범위입니다. 쓸 일이 드물어서 키는 나중에 정합니다.
- 연산자 두 번의 뜻: 처음에는 `==`에 맞춰 덩어리로 정했으나, 가장 흔한 작업(객체 하나 복사·삭제)에 키를 따로 두어야 하는 문제가 있어 vim처럼 가장 작은 단위(커서 객체)로 바꿨습니다. `==`는 객체 하나만 정렬하는 것이 의미가 없어서 덩어리로 남긴 예외입니다. 덩어리 전체는 범위(예: `dH` + `dL`, 또는 비주얼 모드)로 다룹니다. 덩어리 범위에 키를 줄지는 정하지 않았습니다.
- `H` / `L`은 지금 Vim 모드에서 비어 있습니다. `J` / `K`까지 범위로 쓸지(예: 같은 계층 전체)는 정하지 않았습니다. 단독 `K`는 3번의 hover로 제안했으므로, 쓴다면 연산자 뒤에서만 범위가 됩니다.

## 2. `.` 반복

마지막 변경을 그대로 반복합니다. Grasshopper 작업은 반복이 많습니다.

- `i1g`(입력 1에 연결하고 graft)를 한 뒤 `j`로 옆 객체에 가서 `.`
- 같은 출력을 여러 입력에 차례로 꽂기, 같은 데이터 연산을 여러 파라미터에 걸기

1번의 명령 구조(연산자 + 범위)가 있으면 "마지막 명령"을 그대로 다시 실행하면 되므로 거의 공짜로 따라옵니다.

## 3. 진단으로 점프 (LSP의 `]d`, hover `K`)

- `]e` / `[e`: **오류·경고가 난 컴포넌트로 다음 / 이전 이동.** 큰 정의에서 빨간 컴포넌트를 찾느라 화면을 뒤지는 일이 사라집니다.
- `K`: 선택한 출력의 **데이터 트리 구조**(경로 수, 항목 수, 타입)를 띄웁니다. flatten / graft를 걸기 전에 확인하는 용도입니다.
- 더 나아가 Grasshopper용 진단 도구로 확장하는 제안은 [진단 도구](diagnostics-ideas.md)에 따로 정리했습니다.

## 4. 주석 = 비활성화 (`gcc`)

nvim에서 `gcc`는 줄을 주석 처리합니다. Grasshopper에서는 **컴포넌트 비활성화(Enable 토글)**가 정확히 같은 역할입니다.

- `gcH`: 상류 전체 / `gcL`: 하류 전체 / `gcc`: 커서 객체를 끄고 켜기 (1번의 "연산자 두 번" 참고)
- 비주얼 모드에서 `gc`: 선택한 객체들을 끄고 켜기
- 같은 방식으로 프리뷰 토글도 붙일 수 있습니다.

## 5. 바꾸기 `c`, 끼워 넣기

- `c`: **와이어를 유지한 채 컴포넌트 종류만 교체.** 예를 들어 Division을 Multiplication으로 바꾸면 파라미터 이름이나 번호로 와이어를 다시 잇습니다. Grasshopper에는 이 기능이 기본으로 없어서, 지우고 다시 연결해야 합니다.
- 끼워 넣기 (vim의 `o`, 아랫줄 열기): 지금 객체와 그 자식 사이 와이어에 **새 컴포넌트를 끼워 넣습니다.** 출력[0] → 새 입력[0], 새 출력[0] → 원래 받던 입력으로 연결됩니다. `o`는 지금 출력 고르기에 쓰고 있어서 다른 키가 필요합니다.
- 둘 다 `:` 컴포넌트 검색(로드맵)과 묶입니다.

## 6. 찾기와 표시

- `/이름` → `n` / `N`: 닉네임이나 컴포넌트 종류로 찾아 차례로 이동
- `*`: 지금 컴포넌트와 **같은 종류**를 모두 순회
- `m{a}` / `'a`: 자주 오가는 컴포넌트에 표시를 남기고 바로 점프
- `Ctrl+o` / `Ctrl+i`: 이동 기록 (hjkl 설계 때 보류한 것)

## 7. 그 밖에

- **복사·붙여넣기 레지스터** (`y` / `p`, `"a`): 내부 와이어째 복사해서 지금 객체 오른쪽에 붙이고, 출력을 자동으로 연결
- **매크로** (`q{a}` … `q`, `@a`): 키 입력을 녹화해서 재생
- **`:g/패턴/명령`**: 조건에 맞는 컴포넌트에 일괄 적용 (예: 모든 Mesh 프리뷰 끄기, 닉네임 일괄 변경)
- **which-key**: `d`를 누르면 이어서 누를 수 있는 키 목록을 HUD에 표시해서, 키를 외우지 않아도 찾을 수 있게 하기

## 우선순위 제안

1. **연산자 + 범위(hjkl 모션) + 비주얼 모드**: `d` `y` `c` `=` `gc`가 모두 같은 범위 문법을 공유하므로, 다른 기능들이 이 위에 올라갑니다. 문법의 뼈대를 먼저 잡습니다.
2. **`.` 반복**: 1번이 있으면 거의 공짜입니다.
3. **`]e` 진단 점프와 `gcc` 비활성화**: 구현이 작으면서 체감이 큽니다.
4. **`:` 검색 → `c` 교체 / 끼워 넣기**: 컴포넌트 생성과 함께 가장 큰 작업입니다.
